I started my writing journey on LinkedIn. It's still my main public channel for my posts. LinkedIn is the place where my writing habit actually took hold, and I'm not looking to replace it.

This blog is something else, a place for my personal, more code-heavy stuff that should not in a LinkedIn post: a config snippet with real context around it, or a short note on a decision I made and why, or a document that's more useful as a permanent, linkable page than as a feed post.

I keep the setup to be simple, on purpose. The goal is proving the pipeline works at all.
- **Use built-in themes**, no custom theme. I almost went with a popular fuller-featured theme before publishing the first post, which would have meant fighting with `remote_theme` build config and a forked starter repo. It was caught before any real cost, and I picked the plain option instead.
- **No custom domain, no plugins, no extras**. Start with Markdown files in a `_posts` folder, built by GitHub's default Jekyll pipeline. If this turns into a habit worth investing more in, those are easy additions later.
- **Separate from LinkedIn**. No cross-posting from LinkedIn. Two channels, two different jobs.

If you're reading this, the pipeline works: I wrote this in Markdown, committed it, and GitHub built and served it without me touching a single config file by hand. That was the whole point of this first post.
